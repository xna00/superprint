# 技术亮点报告

本文聚焦本项目中真正具有技术深度的三项工程亮点：类型级 SQL 引擎（TypedSQL）、前后端类型穿透的零路由 RPC、以及 QuickJS 引擎下的 React 原生 GUI。每一项都遵循同一哲学——**让类型系统承担"契约"职责，消灭重复代码与运行时错误**。

---

## 一、TypedSQL：类型级 SQL 引擎

### 做法

`server/typed-sql/typed-sql.ts`（363 行）是一个**纯类型层的 SQL 类型推导器**，没有代码生成、没有运行时解析。核心思路：把 SQL 字符串字面量当作输入，直接用 TypeScript 模板字面量类型去"解析"它。

**表结构推导**：`SchemaFks<DDL 字符串>` 直接解析 `CREATE TABLE IF NOT EXISTS ...` 的列定义，产出表结构类型；`ResolveFks<...>` 处理列级 `REFERENCES` 外键推导。

```ts
SchemaFks<"CREATE TABLE IF NOT EXISTS user (id INTEGER PRIMARY KEY, name TEXT NOT NULL)">
// → { user: { id: { def: number }, name: { def: string } } }
```

**语句模式匹配**：`_MatchSelect` / `_MatchInsert` / `_MatchUpdate` / `_MatchDelete` 用模板字面量类型拆出 `cols` / `from` / `where` / `values` / `returning` 各片段，再分别推导返回类型与 `@param` 参数类型。

```ts
db.prepare(
  `SELECT user.id, user.name FROM user WHERE user.id = @id`
).get({ id: 1 })
// 返回 { id: number; name: string }，参数必须是 { id: number }
```

**精细的类型推导**：
- 枚举：`CHECK (status IN ('pending','confirmed'))` → `"pending" | "confirmed"`
- 聚合：`COUNT(*)` → `number`，`SUM/AVG/MAX/MIN` → `number | null`，且刻意要求聚合位于表达式开头，杜绝被 `COALESCE` 等函数包裹时的误判
- 可空收窄：WHERE 中 `T.C IS NOT NULL` → `NonNullable`，`T.C IS NULL` → `null`
- JOIN 别名：`LEFT JOIN` / `INNER JOIN` 解析出别名到表的映射，`T.C` 按别名取列类型
- 参数对齐：`IN` / `BETWEEN` / `=` / `LIKE` / `IS NULL` 各分支提取 `@param`，与对应列类型绑定——写错参数名或类型直接编译报错

**运行时零开销**：`TypedDb.prepare(sql)` 只是把类型断言桥接到 `node:sqlite` 的 `all/get/run`，不存在任何 SQL 生成或运行时解析。

### 亮点

- 表结构（`db.ts` 的 DDL）就是唯一数据源，不存在 ORM 常见的"模型与库不同步"
- 全部收益在编译期，运行时成本为零
- 配套 1064 行的类型测试（`typed-sql-test.ts`）与中英文约定文档（`types-sql-conventions.md`），是按基础设施标准维护的

## 二、前后端类型穿透：零路由 RPC

### 做法

服务端与客户端之间没有 API 定义文件、没有路由注册表，契约只存在于服务端函数的 TypeScript 签名里。

**类型单向流动**：`server/api/index.ts` 导出命名空间（`computer` / `printTask` / `weixin`...），`tsc --emitDeclarationOnly` 生成 `.d.ts`，再由 `api/scripts/copy-types.js` 拷贝并正则清理服务端特有的 node 类型（`DatabaseSync` → `any`、去掉 `node:http` / `undici-types` 导入），产出 `api/__types__/`。客户端 `import type { Api } from "./__types__/index.js"` 后即获得完整类型树。

```ts
// 服务端：函数签名即契约
export const getPrinterKfLink = async (printerName: string) => { ... }
export const regeneratePrinterBindKey = async (printerId: number) => { ... }
```

**客户端 Proxy 魔法**（`api/index.ts`）：`createHandler` 返回递归 Proxy，每次属性访问都拼接 URL 路径，最终调用时按函数名前缀 `get` 自动选择 GET（参数 JSON 进 `?data=`）或 POST（body JSON）。

```ts
api.computer.getPrinterKfLink(name)              // GET  /api/computer/getPrinterKfLink?data=["..."]
api.computer.regeneratePrinterBindKey(printerId) // POST /api/computer/regeneratePrinterBindKey
```

**服务端反向解析**（`handler.ts`）：`parseFn` 把 URL path 拆段，`segs.reduce((prev, curr) => prev?.[curr], api)` 反向走到导出的函数直接调用——API 函数本身即路由。

### 亮点

- **接口永不漂移**：服务端改签名，客户端编译直接报错，从根上消灭前后端不一致
- 前端零 API 定义代码，新增接口无需任何注册动作
- `copy-types.js` 的类型清理脚本，暴露了 `.d.ts` 会泄漏服务端 node 类型这一真实环境问题并加以解决

## 三、QuickJS + React：原生 GUI 渲染

### 做法

客户端（`printdriver-quickwin/`）运行在 quickwin 提供的 QuickJS 引擎上，通过 React reconciler（`quickwin/lib/react-qw/reconciler.js`）把 React 组件树渲染成 Windows 原生控件（`<w type="STATIC">`、`<Button>`、`ListView` 等）——一套 React 代码，编译为原生 Windows 窗口程序，无需浏览器外壳。

**技术含量体现在**：
- mupdf-wasm 在 worker 里渲染 PDF 页面为位图再交给打印管线（`print-worker.ts`）
- 二维码用 lean-qr 生成模块矩阵，手工按 `scaleFactor` 放大为 DPI 对齐的位图（`Math.round(size * scaleFactor)` + `SS_CENTERIMAGE`），解决高 DPI 下控件尺寸与位图失配导致的边框跳变/不可逆放大
- 自动更新、安装/卸载、快捷方式白名单管理等完整的桌面软件分发机制

### 踩坑示例

换用 lean-qr 后二维码弹窗白屏。根因是 quickwin 的 TextDecoder polyfill 只支持 utf-8/utf-16 标签，而 lean-qr 默认编码模式含 shift_jis，测试时懒执行 `new TextDecoder("sjis")` 抛 `RangeError`，异常发生在 React `useEffect` 里导致弹窗白屏。修复方式是在 `generate()` 显式限定模式：

```ts
generate(text, {
  minCorrectionLevel: correction.M,
  maxCorrectionLevel: correction.M,
  modes: [mode.numeric, mode.alphaNumeric, mode.ascii, mode.utf8],
})
```

这类"受限运行时 + 库的隐式能力假设"问题，只有在真实运行环境中才能暴露，是资源受限引擎开发的典型样本。

## 四、为什么这套架构适合 AI 时代

- **类型契约 = AI 的即时反馈回路**：AI 生成的代码不可能一次正确，但类型错误是它能读懂、能自我修正的精确报错。TypedSQL 写错参数名、API 调用传错字段，`tsc` 立刻指出位置，试错-修复循环被压缩到编译层面。
- **声明即 spec**：DDL、函数签名、导出命名空间就是权威接口描述。AI 写新功能时，上下文里的类型定义比自然语言需求更可靠——契约写在类型里，AI 想违反都难。
- **前提**：约定文档（如 `types-sql-conventions.md`）必须进入 AI 上下文，否则 AI 生成的 SQL 一旦超出模板语法，类型推导退化为 `unknown`，安全网即失效。
